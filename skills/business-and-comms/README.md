# Business & Communication Skills

Skills for status updates, meeting follow-ups, and consistent writing.

- **[weekly-status-update](weekly-status-update)** — Turn git history or notes into an outcome-first weekly update with blockers.
- **[meeting-notes-to-actions](meeting-notes-to-actions)** — Pull decisions, owned and dated action items, and open questions from a transcript.
- **[incident-postmortem](incident-postmortem)** — Write a blameless postmortem with impact, timeline, root cause, and owned action items.
- **[release-notes-writer](release-notes-writer)** — Turn commits and PRs into user-facing release notes, breaking changes first.
- **[design-doc-writer](design-doc-writer)** — Write a design doc with goals, non-goals, alternatives, risks, and a rollout plan.
- **[decision-memo](decision-memo)** — Frame a choice, compare options on agreed criteria, and lead with a recommendation.
- **[explain-for-stakeholders](explain-for-stakeholders)** — Rewrite technical updates for non-engineers, with the bottom line first and a clear ask.
- **[code-review-comments](code-review-comments)** — Write labeled, kind, actionable review comments so authors know what blocks the merge.
- **[customer-support-reply](customer-support-reply)** — Draft support replies that answer first, give clear steps, and never overpromise.
- **[technical-blog-post](technical-blog-post)** — Write engineering posts built on a real problem, real numbers, runnable code, and trade-offs.
- **[runbook-writer](runbook-writer)** — Write on-call runbooks with branching triage, exact commands, rollback, and escalation.
- **[job-description-writer](job-description-writer)** — Write job postings with real work, few must-haves, the pay range, and the hiring process.
- **[interview-scorecard-writer](interview-scorecard-writer)** — Build structured interview kits with behavioral anchors and write evidence-based feedback.
